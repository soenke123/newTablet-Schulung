# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

"Master PDF Skill" (formerly "PDF Werkstatt"; `MASTER_PROMPT.md` still uses the old name) – a browser-only PDF page manager (open, reorder, rotate, duplicate, delete, merge, export) with drawing and PDF comments. Vanilla JS, PDF.js for rendering, pdf-lib for export. All UI text, status messages, test names and the README are in **German**; keep new user-facing strings German.

Core product promise: PDFs are processed locally only. Do not add uploads, analytics, telemetry or other network calls.

Deployment targets: (1) a Skill in MPSkills on the user's website (`..\..\Webauftrtitt\MPSkills\tools\`, static Vercel site, no build process); (2) later a Tauri Windows app (exe with own icon, registered for `.pdf`). Therefore: **no build step, no npm runtime dependencies, all paths relative** – the folder must work unchanged when copied into either target.

## Master prompt (target specification)

`MASTER_PROMPT.md` is the full product spec (features, shortcuts, architecture, tests, phases 1–5). It is a **reference, not a task list to execute at once**: the user works through it step by step together with Claude. Only implement the part the user asks for in the current step. The plan for the page-content tabs (Zeichnen → Kommentieren → Einfügen, and which tools stay annotations vs. get flattened on export) is in `PLAN_SEITENBEARBEITUNG.md`. Key constraints from it that apply to every change: vanilla JS + ES modules (no frameworks), no CDNs/external resources, no fake/decorative features (disable or omit what doesn't really work), keep UI and document processing separate, later Tauri/PWA packaging must stay possible.

## Commands

Run the app: double-click `Master PDF Skill starten.bat` (user's way), or from a shell:

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File tools/server.ps1 -Port 5173 -NoBrowser   # serves the folder on http://localhost:5173/
```

`index.html` cannot be opened via `file://` (browsers block ES modules and the PDF.js worker there). `tools/server.ps1` is a dependency-free static server (Windows PowerShell 5.1, `HttpListener`); it refuses `node_modules`/dot-folders and paths outside the project. Keep it ASCII-only (PS 5.1 reads BOM-less files as ANSI).

Tests (Node.js 20+, no `npm install` needed – there are no dependencies):

```bash
npm test                                   # node --test, picks up tests/*.test.js
node --test tests/history.test.js          # single file
npm test -- --test-name-pattern="Undo"     # single test by name
```

There is no linter or formatter configured. Libraries are vendored in `lib/` (PDF.js 5.7.284 incl. worker, cmaps, standard_fonts, wasm, iccs; pdf-lib 1.17.1 ESM; Tesseract.js 7.0.0 + core (SIMD/non-SIMD LSTM builds with embedded WASM) + German traineddata); versions and update procedure in `lib/README.md`. Import them by relative path, never by bare specifier or CDN. Old browsers: `js/app.js` checks for the very new JavaScript PDF.js 5 relies on (`modernJs`: Map.getOrInsertComputed, Promise.withResolvers, Math.sumPrecise, Uint8Array.fromBase64/toHex) and otherwise imports the official legacy build of the same version from `lib/pdfjs-legacy/` (`pdfjsBuild`, top-level `await import`; worker from the same folder, cmaps/fonts/wasm/iccs always from `lib/pdfjs/`). A classic inline script in `index.html` shows `#old-browser` ("Dieser Browser ist zu alt …") when modules or `Array.prototype.at` are missing or a script under `js/`/`lib/` throws before `app.js` sets `data-ready` on `<html>` (its last line). The Playwright Chromium of the cloud sessions lacks these functions, so it exercises the legacy path.

Browser verification: headless Edge `--dump-dom` returns before module scripts finish – drive it via the DevTools protocol (`--remote-debugging-port`, `DOM.setFileInputFiles` on `#pdf-input`) and poll the DOM instead.

## Architecture

- `index.html` – static markup for all UI; elements are looked up by id from JS (`$('id')`). Buttons in `toolbarIds` are enabled/disabled centrally in `updateControls()`. There is no ribbon row: the topbar tabs (icon `.tab-icon` + `.tab-label`; `fitTabs()` sets `.topbar.tabs-compact` = icons only when the row would overflow, re-checked by a `ResizeObserver` on `.topbar` and in `setMode`) (`.ribbon-tabs.edit-only`, next to the mode switch) are „Datei“/„Seite“ (`.menu-tab`, open the dropdowns `#menu-file` (`file-new`/`file-open`/`file-add`/`file-export`) and `#menu-page` (page tools) via `openTabMenu()`; `.tab-menu` is fixed over the page and closes after a choice, a click elsewhere or Esc, `closeTabMenu()`) and „Zeichnen“/„Kommentieren“ (`aria-pressed`, `showToolbox(name)` toggles `state.box` = `'draw'|'comment'|null`). Each of these has its own tool bar `#toolbox-draw`/`#toolbox-comment` (absolute in `.viewer-area`, kept inside the visible part of `#viewer` by `stageRect()`): `.toolbox-grip` + `.toolbox-items` of `.tb-button`s. Per bar `toolboxPrefs[name] = {dock:'left'|'top'|'top-left'|'top-right'|'bottom-left'|'bottom-right'|'free', x, y, grid}` (stored 'right' from older versions is read as 'left') in localStorage (`master-pdf-skill.toolbox-<name>`); `placeToolbox()` applies it (`toolboxLayout()`: classes `.row` = docked top in one line, `.grid` = `--cols` ≈ √n columns, separators hidden), re-run by a `ResizeObserver` on `#viewer`. Dragging the grip (`boxDrag`, pointer events) moves the bar as a free vertical one; within `SNAP` (16) px of the left/top edge, or with the pointer within `CORNER` (56) px of a corner (`snapAt()`: corners go by the pointer, since a tall bar touches top/bottom almost everywhere; corners keep the bar vertical/grid), `.dock-hint` shows where it docks on release; a double tap on the grip (own detection, works on touch) toggles `grid`. Draw bar: `tool-select|pen|marker`, `tool-shapes` (`data-group="shape"`), `tool-eraser`, `draw-color` (colour dot), `draw-undo`/`draw-redo`/`draw-delete`; comment bar: `tool-c-select`, `tool-c-markup` (`data-group="markup"`), `tool-c-note`, `tool-c-text`, `comment-color`, `comment-list-toggle`, `comment-undo`/`comment-redo`/`comment-delete`. A tool button picks its tool on the first tap (`chooseTool`); tapping the active one again (or a colour dot) opens `#tool-pop` (`toggleToolPop`/`closeToolPop`/`placeToolPop`, `state.popAnchor`): its `.pop-section`s – `#shape-kinds` (`tool-line|arrow|rect|ellipse`), `#markup-kinds` (`tool-c-highlight|underline|strikeout`), `#draw-style`, `#eraser-options`, `#comment-style` (`#comment-colors`, `#comment-size-row`) – get class `.on` from the button's `data-pop`. Group buttons pick `state.toolGroups[group]` (last kind, updated in `setTool`) and show its icon; `renderToolbox()` (called from `setTool`/`renderStyleOptions`/`renderCommentColors`/`updateControls`) updates groups and colour dots. Style controls: `#pen-swatches` rebuilt by `renderStyleOptions()`, `#pen-custom-input` colour input, `#pen-width`/`#pen-opacity` sliders, `#shape-fill` only for rect/ellipse; `#eraser-options` (mode buttons `[data-erase]`, `#eraser-size`) shown instead while the eraser is active; `#comment-colors` from `renderCommentColors()`. In read mode the topbar `.read-only` buttons `#open-pdf`/`#export-pdf` are shown instead.
- Files: `openFiles(files,{replace})` accepts PDFs and images (`isPdfFile`/`isImageFile`): an image becomes a one-page A4 PDF (`imagePdf()` → `pictureFromFile(file, 3000)` → `createImagePdf()` in export.js, upright/across like the picture, 20 pt margin) and is then opened like a PDF (own source, named after the file); drops of images only insert into an open document in both modes (`draggedImagesOnly` for the drop indicator). Encrypted PDFs (`looksEncrypted`) go through `unlockPdf()`: `decryptPdf(bytes, '')` first, on `PasswordError` code 'password' `#pw-dialog` (`askPassword`) until right or cancelled; 'unsupported' → toast. `js/crypt.js`: standard security handler R2–R6 (`fileKey`: algorithm 2/6/7, R5 SHA-256, R6 algorithm 2.B with WebCrypto; MD5/RC4 in JS, AES-CBC via WebCrypto incl. unpadded tricks), crypt filters V4/V5 (`methods`), object keys; two pdf-lib passes with `PDFParser.prototype.parseIndirectObjectHeader`/`PDFObjectStreamParser.forStream` patched (pass 1 collects object streams, pass 2 parses their decrypted copies with the dict of that pass and records the objects inside, which are not decrypted again), then every string/stream is decrypted, /Encrypt removed and the plain bytes saved – sources only ever hold plain bytes. `source.info` = PDF.js `getMetadata().info`. Datei → „Eigenschaften …“ (`#props-dialog`, `openProps`): `state.meta = {title, author, subject, keywords, clean}` (clean default from localStorage `master-pdf-skill.meta-clean`, shows the opened file's info, never copies it) → `buildPdf(…, {meta})` → `setMetadata()` (`PDFDocument.create({updateMetadata: !clean})`). Rest: – „PDF öffnen“ (`#pdf-input`, Strg+O, drops in read mode) replaces the document via `resetDocument()` (asks `confirmDiscard()` first when dirty; clears sources, history, clipboard, thumbnail cache); „PDF hinzufügen“ (`#pdf-add-input`) and drops while editing insert (`insertAt`, recorded in history). `newDocument()` = reset + one blank A4 page.
- Modes: `state.mode` is `'read'` (default on load) or `'edit'`, switched by `setMode()` via the `#mode-read`/`#mode-edit` buttons; `body.mode-read` hides `.edit-only` (tabs, tool bars), `body.mode-edit` hides `.read-only`. In read mode `editing()` is false: no card drag, card actions, context menu, long press or editing shortcuts; scrolling updates the active card via `markActive()` without rebuilding the list and `selectPage()` scrolls instead of re-rendering.
- `js/app.js` – the whole app in one module, written in dense, mostly one-line-per-function style. A single mutable `state` object holds everything:
  - `state.sources: Map<sourceId, {name, bytes, pdf, pageSizes, color, tint, blank?}>` – one entry per opened file; keeps the original bytes (for pdf-lib export), the PDF.js document (for rendering) and `pageSizes[i] = {x, y, width, height, rotate}` (the PDF.js `page.view` box + `/Rotate`) read once on open. Colors come from `sourcePalette` (8 entries, cycles over non-blank sources).
  - Blank pages: `insertBlankPage()` generates a one-page PDF (`createBlankPdf`) per page size and registers it as a hidden source (`blank: true`, excluded from legend/document name via `documentSources()`/`activeSources()`), so rendering, export, undo and clipboard need no special case.
  - `state.pages: [{id, sourceId, pageIndex, rotation}]` – the *virtual* document. Page operations only edit this array; source PDFs are never modified. `id`s come from the shared `state.nextId` counter (also used for source ids). `rotation` is absolute and starts at the page's original `/Rotate` (`pageSizes[i].rotate`); the card label shows only the difference.
  - `p.marks` (optional) – drawings on that page: `[{id, type:'ink'|'line'|'arrow'|'rect'|'ellipse', color, width, points:[x0,y0,…], opacity?, blend?}]` (shapes: drag start/end; highlighter = ink with `blend:'multiply'`) in PDF user space of the unrotated source page, so they follow sort/rotate/duplicate/clipboard and need no conversion on export. Marks arrays are **replaced, never mutated** (`createSnapshot` copies pages shallowly, undo snapshots share them).
  - `p.comments` (optional) – PDF comments on that page, see `js/comments.js` for the shape (`kind`, `color`, `text`, `author`, `date`, `rect`, `quads?`, `replies`, `orig?`), same PDF space and same replace-never-mutate rule as marks.
  - `state.dirty` – set by `recordHistory()`/undo/redo, cleared only by a successful export of the whole document in current order; drives the "Nicht gespeichert" badge, the `●` title prefix and the `beforeunload` warning.
  - `selected` (Set), `anchor` (shift-range start), `activePageId` (page shown in the viewer).
- Render flow: mutate `state` → `renderPageList()` (sidebar thumbnails, legend, controls) and `renderViewer()` → `renderReader()` for both modes (read: all pages, in pairs via `.reader-row` when `state.spread`; edit: all pages too (`singleView()` is now always false; it used to show only the active page until a tool bar was opened); `showToolbox()` re-renders when that changes, and the scroll tracking/`selectPage()` use `singleView()` instead of `editing()`). A debounced `ResizeObserver` re-renders the viewer, but waits while a drawing/comment gesture is running (it would replace the page under the pen). Pages are sized placeholders `.reader-page` inside `.viewer-content`, canvases drawn/dropped by an `IntersectionObserver`; an already drawn canvas of the same page is carried over as placeholder until the new rendering is done (no white flash on zoom).
- Text layer (`drawTextLayer` after `clearReaderPage` in app.js): after each canvas render a PDF.js `TextLayer` (`.textLayer.text-layer`, placed right after the canvas, below the mark/comment/form layers which are `pointer-events:none`) is built from the cached `loadPageText()` items, `--total-scale-factor` = viewport px per pt; rotation via `data-main-rotation` CSS. The browser does selection/copy itself (Strg+C, context menu, long press). CSS (end of app.css, trimmed from pdf_viewer.css) turns it off with `pointer-events:none` while a `tool-*` body class is set. `.selecting` (pointerdown → document pointerup) stretches `.endOfContent` so drags between lines do not jump. The keydown handler lets Strg+C/X through when `textSelected()` (non-collapsed selection inside `#viewer`) instead of copying pages.
- View (`js/view.js`, pure): `state.zoom` is absolute (1 = 100 % = 96/72 CSS px per pt, `CSS_UNITS`), `state.fit` is `'auto'|'width'|'page'|null` (null = manual zoom); with a fit mode `renderReader()` recomputes `state.zoom` via `fitZoom()` (one uniform scale for all pages, based on the widest/tallest row). View controls live in `.view-actions` in the document toolbar (no ribbon tab); `#view-spread`/`#view-focus` carry `.read-only`. Zoom changes go through `applyZoom(zoom, viewAnchor(point))` + `restoreAnchor()` so the point under the cursor/fingers stays put; pinch (Ctrl+wheel = touchpad, two-finger touch events, Safari `gesture*`) previews with a CSS transform on `.viewer-content` and commits after the gesture (`commitZoom`). `.viewer` has `touch-action: pan-x pan-y` so the browser does not page-zoom.
- Focus mode (`setFocus`, `body.focus-mode`, read mode only): hides all chrome, black viewer, Fullscreen API when allowed (fallback: in-window); `fullscreenchange` ends it; `#focus-bar` appears on pointer activity.
- Search (`js/search.js` pure + search block in app.js): `loadPageText()` caches PDF.js text content per `sourceId:pageIndex` (`textCache`/`textValues`, cleared in `resetDocument()`); hits `{pageId,pageNo,key,pieces,snippet}`; `drawHighlights()` adds `.hl-layer` to drawn pages using `pieceRect()` + `viewport.convertToViewportRectangle`; results are recomputed when the page list changes (`searchStale()` in `renderViewer()`). There is no framework or diffing; lists are rebuilt. Thumbnails are therefore cached: `requestThumbnail()` renders each `sourceId:pageIndex:rotation` once into a JPEG blob URL (`thumbUrls`), at most two at a time, triggered by an `IntersectionObserver` on the `<img>` (lazy); the `<img>` gets its `aspect-ratio` from `pageSizes` so the layout does not jump.
- Export (`exportPdf` in app.js → `buildPdf` in `js/export.js`): the dialog (`askExport`) offers „Ganzes Dokument“ (default), „Aktuelle Seite“ and „Auswahl“ (default for a multi-selection or the context menu's „Auswahl exportieren“; page list via `js/ranges.js`, e.g. `1-3, 4, 10-12`, prefilled with the selection) and – only without `showSaveFilePicker` – the file name. `buildPdf` does **one `copyPages` call per source** (shared fonts/images are copied once; repeated pages still get separate page objects) and applies `setRotation(p.rotation)`. `p.rotation` is an absolute angle, both here and in PDF.js `getViewport({rotation})` (which overrides the page's own `/Rotate`). Progress goes to `#export-progress`; on write failure the writable is aborted.
- Word export (`exportDocx` in app.js → `js/docx.js`, pure): menu `file-export-docx`, read-mode button `export-docx` (`.wide-label` hides „Als “/„ exportieren“ below 600 px); reuses `askExport(scope, askName, 'docx')` (title + `#export-docx-hint`), `pickSaveHandle(name, 'docx')` (`fileTypes`), `suggestedFileName`/`cleanFileName` take the extension. Per page `docxPage()`: `loadPageText()` items, `getOperatorList()` → font names from `page.commonObjs` and image placements (`imageOps()` tracks the CTM through save/restore/transform/form XObjects; image objects via the callback form of `objs.get` in `pdfObject()`, which waits for them; `imageSource()` turns PDF.js image data into a canvas; `placedImage()` draws each image as it appears – flips, rotation – into its own canvas → PNG, JPEG above 600 k px). The layout rotation is `uprightRotation()` (the direction most text runs in, so sideways pages give normal lines), not `p.rotation`. `layoutPage()` in view space: `readSegments()` (lines, split at wide gaps ≥ 1.4 em into segments; PDF.js whitespace items only mark a space, they can reach into the next column), `guessBold()` (anonymous `CIDFont+F1` fonts: the most used one is regular, others bold), `findTables()` (rows of ≥ 2 segments starting at the same x columns, each inside its column; new row after a gap > 1.55 em), `mergeRows()` (non-table gaps → tab), `groupParagraphs()`/`joinLines()` (paragraph breaks, hyphenation), headings by size relative to the body size, images/tables placed before the first paragraph below them. Pages without text are rendered to one JPEG (150 dpi). `buildDocx()` writes one section per page (size/margins, nextPage) and a stored ZIP (`zip()`, `crc32()`, no compression). Not exported: marks, comments, form values (it converts the PDF content). The dialog's `#export-docx-options` (radios `export-docx-mode` 'fixed'|'flow', choice in localStorage `master-pdf-skill.docx-mode`, default 'fixed') picks the mode; the above is 'flow'. Mode 'fixed' („Wie im PDF“, `docxFixedPage()`): `renderPagePicture()` renders the page twice at 150 dpi (≤ 2200 px), once normally and once with `ctx.fillText`/`strokeText` replaced by no-ops (PDF.js draws loaded fonts with them) → the text-free picture is the JPEG page background; `textInk()` compares both under each item → text colour (hex, near-black left out) and `ink` (share of text pixels; `guessBold()` then calls an unnamed font bold only above 1.35× the regular one's ink, so italics stay plain). `layoutFixed()` (docx.js) groups segments that continue each other (same x, even spacing, same size) into text boxes `{x, y, width, height, line, lines}` (y = first baseline − line + 0.22 em, the descent Word leaves under a line with exact spacing); `buildDocx()` writes such a page as one paragraph with the background (`backgroundXml`, anchored behind the text) and one `wps` text box per group (`textBoxXml`, in `mc:AlternateContent`, no wrap, no insets, one paragraph per PDF line with exact line spacing). `letterSpacing()` keeps letter-spaced single-character items together.
- Page operations are shared by toolbar buttons, keyboard shortcuts and the context menu (`menuItems()`); add new ones in all three places. Paste/duplicate insert via `insertAfterSelection()`.
- Context menu (`#context-menu`): right click / context-menu key on a card, or on touch/pen a long press (`press` state machine on `pointerdown`/`pointermove`/`pointerup`: hold 450 ms → release opens the menu, move starts a pointer-based reorder with edge auto-scroll). Native HTML5 drag is suppressed for non-mouse pointers (`state.lastPointer`) because it is unreliable on touch.
- Drawing (`js/annotations.js` pure + drawing block at the end of app.js): `state.tool` is `null` or a `data-tool` name, only active in edit mode with the „Zeichnen“ bar shown (`state.box`; `showToolbox`/`setMode`/`resetDocument`/Esc reset it; `body.tool-*` sets `touch-action:none` on pages). `state.pen`/`state.marker` hold the current style `{color, width, opacity, fill?, custom}` (shapes use the pen style; `custom` = last own colour shown in the rainbow swatch), `state.eraser = {mode:'object'|'area', size}`; `state.markSel = {pageId, markId}` is the element selected with „Auswählen“ (Entf/`draw-delete` remove it, the style controls restyle it, Esc deselects before ending the tool). Sliders and the colour input call `previewStyle()` on `input` (repaint only, no history) and `applyStyle()` on `change` (one history entry, skipped when nothing changed). `pageTransform(box, rotation, scale)` maps PDF ↔ view px exactly like PDF.js `getViewport`; each `.reader-page` keeps it in `wrap._map` and has two `.mark-layer` SVGs – `.highlights` (mix-blend multiply) under `.strokes` – built by `markLayers()`, filled by `paintMarks()` via `markSvg()`; thumbnails get them inside `.thumb-frame`. Canvas swaps in `drawReaderPage`/`clearReaderPage` must only replace the canvas/`.hl-layer`, not the mark layers. Pointer gestures on `#viewer` live in `drawGesture` (not `gesture`, which is the pinch-zoom preview): previews repaint the layers with a temporary marks list, the history entry is recorded once on release; a second pointer cancels (pinch zoom keeps working); resizing with „Auswählen“ uses the handles of the selection frame (`markHandles`/`handleAt`, `resizedMark()` in view space → `scaleMark()`; lines/arrows move their ends); rect/ellipse lines run inside the dragged box (`strokeBox`), filled ones are drawn as a group (SVG `<g opacity>`, export: transparency-group form XObject); the eraser samples along the swipe (`markHit` in mode 'object'; `eraseMarks()` in mode 'area' cuts strokes into new ink marks with fresh ids, shapes become ink without fill; `eraseCursor()` shows the size as an HTML circle in the page wrap). Copy/paste of marks (`draw-copy`/`draw-paste`, Strg+C/X/V/D while the draw bar is open and a mark is selected/copied): `state.markClip = {mark, pageId, at, count}`, `insertMarkCopy()` puts the copy on `currentPage()` via `placeMark()` (annotations.js: shift 12 pt per repeated paste on the same page, pushed back inside the page box). Export: `drawMarks()` in `js/export.js` flattens marks into the page content (vector, round caps, highlighter first with an ExtGState `CA` + `BM /Multiply`; `opacity` → `CA`, the fill of rect/ellipse → `ca` + `B` operator) after giving the page its own `/Contents` array – copyPages shares even direct objects between repeated pages.
- Comments (`js/comments.js` pure + comments block at the end of app.js, `writeComments` in `js/export.js`): on open, `readPages()` reads each page's `getAnnotations()` through `importAnnotations()` into `p.comments` (replies via `/IRT` attached to their thread, popups owned by their parent) and stores per source page `annots[i] = {owned, kept}` (ids of the source annotations the comments stand for / of those the canvas keeps drawing). Kinds with `redraw` (note, highlight, underline, strikeout, squiggly, freetext) are hidden in the canvas and painted by the app in two `.comment-layer` SVGs (`.cm-under` multiplied, `.cm-over`); other kinds (Ink, shapes, Stamp, Caret) stay in the canvas. Text boxes (`c-text`, kind `freetext`): `color` = text colour, `fontSize`, optional `fill` (background) and `border` (frame colour, `FREETEXT_BORDER` pt inside the rect; palettes `FREETEXT_FILLS`/`FREETEXT_BORDERS`, '' = none, rows `#comment-fill-row`/`#comment-border-row` in the pop, `applyTextBox()`, defaults for new boxes in `state.ftstyle`; export /C, /BS /W, /MK /BC; import from PDF.js `color`, `borderStyle.width`, `borderColor`; both part of `orig`/`commentChanged`), rect from `freeTextRect()` (grows with the text, measured with the export's Helvetica metrics via `textMetrics()`), painted by `freeTextElement()` turned with the page; exported as FreeText with /DA and a Helvetica /AP (`freeTextAppearance`, unencodable characters become „?“). `c.status = {state, author, date, orig?}` (COMMENT_STATES) is read from hidden Review replies (/State, /StateModel) and written back as one; `commentFilter` filters only the list (`commentMatches`). Visibility is per page copy: `prepareAnnotations()` sets `noView` in the PDF.js `annotationStorage` right before every `page.render()` (`annotationMode: ENABLE_STORAGE`, read synchronously by PDF.js), and `thumbKey()` includes kept comments deleted on that copy. Text markup selects characters via `charIndexAt()`/`selectionQuads()` on the search's `loadPageText()` data, with character widths measured once per page by `measuredText()` (canvas `measureText`, `item.advances`). Tools work only in the editing view; without a tool (also in read mode) a click on a comment selects it and opens `#comments-panel` (`renderCommentPanel()`, rebuilt from `renderPageList()`, keeps focus/typed text; `panelFrozen` while a textarea commits). `state.commentSel = {pageId, commentId}`. Export: `buildPdf(…, {ownedAnnots})` maps PDF.js ids (`12R`) to the copied refs (`copiedAnnotRefs`, same /Annots order) and `writeComments()` rebuilds each page's /Annots: unchanged imported comments keep their original objects (+ popup, replies) on the first copy, changed or repeated ones are copied, new ones get `/AP`, `/Popup`, replies `/IRT`; markup has the Print flag, notes NoZoom|NoRotate without Print; non-comment annotations stay untouched.
- Palm rejection (block after the comment pointer handlers in app.js): `state.penOnly`/`state.penSeen` from localStorage `master-pdf-skill.pen-only` ('1'/'0'; the first pen `pointerdown` with a tool turns it on and toasts once). Capture-phase `pointerdown/move/up/cancel` listeners on `#viewer` run before the tool handlers: with `penOnly` and a tool active, touch pointers never reach them (`stopImmediatePropagation`); one finger scrolls `#viewer` by hand (`fingerScroll`, with `fling()` inertia – the pages have `touch-action:none` while a tool is active), a second finger leaves it to the pinch zoom, touches during a pen gesture (`penBusy()`, gestures carry `pointerType`) are ignored. The pinch `touchstart` also ignores `touchType==='stylus'` touches (iPad Pencil). Toggle `.pen-only-toggle` (`draw-pen-only`/`comment-pen-only`, `.pen-only-item` hidden until a pen was seen; `toolboxLayout()` counts only visible buttons).
- Insert bar „Einfügen“ (`#toolbox-insert`, `state.box==='insert'`; block after the palm-rejection block in app.js): it shares the marks and the tool `select` with the draw bar (`#tool-i-select` has `data-tool="select"`, `markBox()` = draw or insert box, `drawing()` uses it). Pictures and signatures are image marks `{type:'image', src (PNG/JPEG data URL), points [x0,y0,x1,y1], rot, label}` (annotations.js: `imageMatrix` = `cm` of the export, `imageViewMatrix` for the SVG `<image>`; `rot` = page rotation when inserted, so they stand upright as shown). `insertPicture()` centres them in the visible part of `currentPage()` (`visibleSpot`), switches to `select` and selects them; corner handles keep the proportions (`resizedMark`), the style pop has nothing for them (`styleContext().image`), area erasing skips them, „Ganze Elemente“ removes them. `pictureFromFile()`: PNGs up to 2000 px stay as they are, everything else is re-encoded through a canvas (EXIF orientation applied, max 2000 px). Resize: `resizedText()` – corners scale `size` (and `boxWidth`), side edges set `boxWidth`. Export: `embedTextFonts()` + text drawn as BT/Tf/Tj in the frame matrix (searchable).
- Forms (`js/forms.js` pure + forms block before the demo code at the end of app.js, `writeForms` in `js/export.js`): `readPages()` also returns `fields[i]` per source page (`importFields()` from the same `getAnnotations()` call: `{id, name (fully qualified), kind 'text'|'checkbox'|'radio'|'choice', rect, value, readOnly, rotation, …}`, push buttons/signatures/hidden left out), stored as `source.fields`. Values: text = string, checkbox/radio = on-state name or 'Off', choice = array of export values. `state.forms` (Map `fieldKey(sourceId,name)` → value) holds only changed values, so fields of different files stay separate; it is part of the history snapshot and of `thumbKey()` (`filledKey`). Every field object has an `owner` (source id, set in `openFiles`; `NEW_FIELDS` = 'new' for created fields), keys are `keyOf(f)`. Display: `prepareFields()` (called from `prepareAnnotations()` right before every render) puts changed checkbox/radio/choice values into the PDF.js annotation storage (PDF.js draws them); changed **text** fields get `noView` and are drawn by the app instead (the input with class `.own`, `fieldTextLayer()` SVG in thumbnails) because PDF.js draws auto-sized multi-line fields with one huge line – and reports `fontSize` for "0 Tf" as the one-line size, hence `fieldFontSize()`. `formLayer()` adds `.form-layer` with one control per widget (`formControl`: input/textarea, select, button role checkbox/radio; positioned by `fieldFrame()`, turned with the page) on reader pages, hidden while a tool is active; unchanged text is transparent (the canvas shows it), `.editing`/`.pending` make it visible. `commitField()` (text on blur, Enter/Esc; others on change/click) = one history entry, then `refreshField()` syncs all widgets of the field and redraws the affected canvases in place (no viewer rebuild, so focus stays); the resize re-render waits while a field has focus (`fillingField()`). Undo/redo shortcuts work in read mode too. Export: `buildPdf(…, {formValues})` (`changedFormValues(sourceId)` → Map name → value), `sourceForm()` copies /DR, /DA, /NeedAppearances; `writeForms()` gives each page its own /Annots, clones widgets of repeated pages (`duplicateWidget`, splits a merged field/widget), prunes /Kids to exported widgets, renames clashing root names of different sources (`_2`), writes a new /AcroForm and sets changed values with pdf-lib (`setFieldValue`, new Helvetica appearances; radio values may be option texts with /Opt; on failure /NeedAppearances and no stale /AP); saved with `updateFieldAppearances:false`.
  Creating fields (insert bar, tools `i-field-text`/`i-field-check`, both behind the group button `tool-i-fields` (`data-group="field"`, pop section `#field-kinds`) like the shapes): field marks `{type:'field', kind 'text'|'checkbox', name, points, rot}` in `p.marks` (`isBoxed` in annotations.js: hit test, move, resize – a checkbox keeps its square – delete, undo and copy like pictures; drawn by `markElement` as a dashed `.field-box`, skipped by `drawMarks`). Dragging goes through `shapeMark` → `fieldMark()`, a tap makes `FIELD_DEFAULTS` size; names are automatic and unique (`nextFieldName(kind, usedFieldNames())`, also for pasted copies; copies of a page keep the name = one field). `pageFields()` adds them via `createdField()` (forms.js; multi-line from `MULTILINE_HEIGHT` 30 pt upright, then 11 pt), so they are filled like read fields; they are always drawn by the app (`.own`, checkbox tick via CSS `::after`, `fieldTextLayer` in thumbnails); `refreshMarks()` rebuilds the form layer (`syncFormLayer`). Export: `buildPdf(…, {newFields: changedFormValues(NEW_FIELDS)})` → `createFields()` creates real pdf-lib fields (grey frame, no background, `rotate` = rot with the corner pdf-lib turns around, name clash with read fields → `_2`, same name on several pages = one field with several widgets) and sets the values.
- Edit bar „Bearbeiten“ (`#toolbox-edit`, `state.box==='edit'`, tools `e-*` → `boxOf()`; `markBox()` includes it, so `select` (`#tool-e-select`) and undo/delete work as in the draw bar; block before the demo code at the end of app.js):
  - Text ändern (tool `e-text`): `editPick` gesture (tap = `tokenAt()` = whole non-blank run, drag = one line, preview mark `edit-sel`) → `beginEdit()`: `pageAnalysis(p)` (glyphs of the page **as shown**, i.e. with earlier edits: pdf-lib copy of the source via `libDoc()` or of the preview bytes, `analyzePage()`, cached in `analyses` by `textKey(p)`) → `glyphsIn(rect)`; style from the first visible glyph (`res`, `size`, `th`, `tc`, `rise`, `matrix` = text matrix × CTM) or, when no glyph is found (scan/OCR, form XObject, vertical font), from the PDF.js item + `cover:true`; `sampleColors()` reads `bg`/ink from the canvas. `openEditEditor()` puts an `<input class="edit-editor">` (background `bg`) on the baseline (`editFrame()`); Enter/blur commit (`closeEditEditor` → new edit mark appended, one history entry, `refreshEditedPage()`), Esc cancels. Edit marks `{type:'edit', points (rect), text, old, style, color, font, bold, italic, css, cover, bg}` form an ordered chain per page; each was made on the page as it looked after the earlier ones. They are not drawn in SVG, not selectable/erasable (undo only); a word changed before is simply changed again (a new edit).
  - Preview: a page with edits is rendered from `editedPagePdf(source.bytes, pageIndex, edits)` (export.js, the same `applyEdits` as the export) loaded into PDF.js – `pageDoc(p)` (async, cached in `previews` by `textKey(p)` = `sourceId:pageIndex[:editKey]`, `editKey()` = hash of the edits) is used for the canvas, thumbnails, `loadPageText`, Word export, OCR and redaction rasters; `shownDoc(p)` (sync, resolved docs) for `prepareAnnotations`/`prepareFields`, whose ids go through `idOf` (`annotationIdMap`: same /Annots order, else type + rect). `thumbKey` includes `editKey`.
  - Export (`applyEdits` in export.js, before watermark/marks): content wrapped `q … Q`, then per edit in order `analyzeContent(page, body)` + `replaceText()` (textedit.js): the new codes go into the first text operator in place of the old glyphs (original font when `fontInfo.encode()` has every character, otherwise `/Std size Tf <…> Tj /Orig size Tf` from `standardFor()`), every later glyph on the same line up to a gap of 3 font sizes is placed at its old position + Δ width with TJ offsets (rewrites the operators with removed/shifted glyphs and the ones continuing them; `fresh` = positioned by Td/Tm/T*/BT, per-op `start`/`end` in `glyphs.ops`). Cover edits (or when `replaceText` returns null) append `coverOps` + `textOps`. Standard fonts are embedded right away (`font.embed()` in `standardFont`) so a later edit can read them. Old content streams no page uses are deleted (`dropUnused`).
  - `js/textedit.js` (pure + pdf-lib): `tokenize()` content lexer (strings, hex, arrays, dicts, inline images), `parseCMap()` (bfchar/bfrange/codespace/cid), `fontInfo()` (Type0 Identity-H/V or embedded CMap with /W + DW; simple fonts /Widths + FirstChar, Type3 FontMatrix, standard 14 without widths via `stdWidth(base, ch)`; ascent/descent; `encode(text)` via ToUnicode reverse map or WinAnsi), `readGlyphs()` (q/Q, cm, BT, Tc/Tw/Tz/TL/Ts/Tr/Tf, Td/TD/Tm/T*, Tj/TJ/'/", fill colour g/rg/k/sc/scn → hex; per glyph `adv` in user units, per operator `glyphs.ops[op] = {fresh, start, end, size, th, scale}`), `analyzeContent()`, `replaceText()`, `removeGlyphs()`, `textOps()`, `coverOps()`.
  - Schwärzen (tool `e-redact`): drag = rect (`shapeMark` → `{type:'redact', points}`), tap = token box (`redactWord`), shown black (`.redact-box`), boxed like pictures (move/resize/copy). Export: `prepareEditing()` in app.js renders each page with redactions at 200 dpi, rotation 0 (`rasterizePage`: rendered from `pageDoc(p)`, so edits are already in, annotations as on screen via `prepareAnnotations`, changed text field values via the annotation storage, boxes black; PNG or JPEG, whichever is smaller) and passes `rasters` (page id → `{data, png, box, text}`; text = `textOutside(items, rects)` from `js/editing.js`) to `buildPdf`, which does **not copy** that page: `rasterPage()` builds a new page (MediaBox = box, image + invisible text); only redrawn comments that do not touch a box are passed (`writeComments` with empty refs). After `buildPdf`, `verifyRedaction()` reopens the bytes with PDF.js: any character under a box (`textInside`) or annotation touching one aborts the export before anything is written. `exportDocx` refuses documents with redactions.
  - Wasserzeichen: `state.watermark = null | {text, color, opacity, size 'small'|'medium'|'large', layout 'diagonal'|'horizontal'}` (part of the history snapshot); dialog `#wm-dialog` (`wmDraft`, `setWatermark`); `watermarkLayout()` (editing.js: centred in the page box, slanted along the diagonal as shown, i.e. angle + page rotation, size from Helvetica-Bold widths) is used by `watermarkElement()` (first child of the `.highlights` layer, also in thumbnails) and by `drawWatermark()` in export.js (ExtGState ca/CA, over the content, under marks).
  - OCR: `#ocr-dialog` (current page / all pages without own text; pages are deduplicated per source page), Tesseract.js from `lib/tesseract/` loaded on first use (`getOcrWorker`: `workerBlobURL:false`, `cacheMethod:'none'`, core file picked by `simdWasm`, `langPath` lib/tesseract/lang, OEM 1). Pages are rendered upright as shown at ≤ 300 dpi without annotations; `ocrItems()` (editing.js) turns lines/words into PDF.js-like items (`ocr:true`, `fontName:'ocr'`) stored in `source.ocr[pageIndex]`; `loadPageText()` appends them, so search, text layer, markup, „Text ändern“ (cover mode) see them. Export: `invisibleText` (page id → OCR items outside edit rects) → `invisibleOps()` (Helvetica, `3 Tr`, Tz stretched to the word width). Not part of the history; sets `state.dirty`.
  - export.js helpers: `ownContents()` (own /Contents array, a single stream becomes an array, then `normalize()`), `appendContent()`, `bare()` (pdf-lib resource names come with a slash).
- Autosave „Automatisch sichern“ (`js/autosave.js` + block before the demo code at the end of app.js): while `state.dirty && state.pages.length`, `scheduleSave()` (called from `recordHistory()` and `updateControls()`, 1.2 s debounce; `saveNow()` right away on `visibilitychange` hidden/`pagehide`) writes to IndexedDB `master-pdf-skill`: store `doc` key `current` = `sessionDoc(state, name)` (pages incl. marks/comments/edits, selection, `forms` as entries, watermark, meta, nextId, source list without bytes/PDF.js objects but with `ocr`, `blank`/`blankKey`) and store `sources` = bytes per source id, each written once (`storedSources`), stale ids deleted in the same transaction. Not dirty any more (whole export, `resetDocument()`) → `clearSession()`. On load `offerRestore()` (`autosaveReady` stays false until answered, so nothing is overwritten): `loadSession()` → `#restore-dialog` (Esc blocked; „Verwerfen“ clears) → `restoreSession()` re-opens each source from its bytes (`readPages()` again for pageSizes/annots/fields – PDF.js ids are stable), then `restoredState()` (pages of unreadable sources dropped, selection/active fixed, `nextId` above every saved id). History is not saved. Toggle `#file-autosave` in the Datei menu (`menuitemcheckbox`, off by default, localStorage `master-pdf-skill.autosave` '1' = on (remembered per device), turning off clears the store). The demo (`?demo=1`) never saves. Any new per-document state must go into `sessionDoc`/`restoredState` too.
- Undo/redo (`js/history.js`): `HistoryStack` (limit 50) of `createSnapshot(state)` copies of `pages`/`selected`/`anchor`/`activePageId`/`forms`/`watermark`. Every mutating page operation must call `recordHistory()` **before** mutating. Adding PDFs into a non-empty document is also recorded; export is not. „Neu“/„PDF öffnen“ clear the history (`history.clear()`).
- Drag & drop: one list-level `dragover` on `#page-list` handles both internal page drags (`state.dragId`) and external file drops. `dropTargetAt()` picks the nearest card and before/after (horizontal halves in the multi-column grid, vertical halves when the grid has one column, e.g. the collapsed mini strip) into `state.dropTarget`; `showDropIndicator()` sets `drop-before/after/above/below` classes (CSS bar + "hier" pill). Internal drops → `movePagesTo` → `movePages()` from `js/pages.js`; file drops → `openFiles(files, insertIndexFor(state.dropTarget))`.
- Sidebar: `.collapsed` shows a mini strip (numbers, source color, `.selected`/`.active`) instead of hiding; thumbnails are not rendered while collapsed. Width is the CSS var `--sidebar-width`, set by the `#sidebar-resizer` handle and remembered in `localStorage`. The viewer re-renders via a debounced `ResizeObserver`; stale canvas renders are dropped via a per-element generation counter (`wrap._gen`).
- Page clipboard (`state.clipboard`, Strg+C/X/V) is internal only — page records, not the system clipboard. Delete has no confirm; it toasts and relies on undo.
- Export asks for a file name every time: `showSaveFilePicker` where available (Chromium/WebView2), otherwise the `#export-dialog` fallback + download.

## Known limits (from README)

Word export: „Wie im PDF“ = page picture without text + text boxes (graphics not editable in Word, boxes do not wrap, unknown fonts become Calibri); „Fließtext“ = editable text, not a layout copy (no columns side by side, colours, vector graphics, merged cells; scans as pictures). Text editing is for small changes (the rest of the line moves, but no wrapping into the next line or re-justification; form XObjects/vertical fonts fall back to covering); redaction turns the affected pages into images (links, vector quality and form fields of those pages are lost); OCR: German model only. Autosave keeps unexported work only in this browser (IndexedDB, no undo history); no PWA/offline support yet; forms: filling and creating text fields/checkboxes work, no push buttons, signature fields, form scripts or XFA, created radio groups/choice lists not yet; text marks use the PDF standard fonts (WinAnsi only, no embedded font). Export copies pages into a new PDF, so bookmarks, metadata, layers, attachments etc. are not guaranteed to survive. Corrupt PDFs and certificate-encrypted PDFs fail on open; exports never have a password.


## Version / Windows-Fassung
- `version.json` ist die einzige Quelle der Versionsnummer (aktuell 1.0). `js/version.js` zeigt sie im Menü Datei (`#file-version`). **Neue Windows-Version = Nummer in `version.json` erhöhen**: der Push auf main startet `.github/workflows/master-pdf-windows.yml` (windows-latest), der baut mit Tauri und checkt `downloads/master-pdf/MasterPDFSkill-Setup.exe` + `downloads/master-pdf/version.json` ein; Vercel liefert beides aus (`vercel.json`: no-cache, CORS, exe als Download). Ohne Erhöhung wird nicht neu gebaut (sonst wächst das Repo um jede .exe).
- Hülle: `desktop/master-pdf/` (Tauri 2, in `.vercelignore`). `prepare.mjs` kopiert index.html/version.json/site.webmanifest/css/js/lib/icons nach `dist/` und setzt die Version (1.0 → 1.0.0) in tauri.conf.json/Cargo.toml. Rust (`src-tauri/src/main.rs`) liefert nur die Startdatei: `launch_file_name`/`launch_file_bytes` (argv, rohe Bytes). NSIS-Installer pro Benutzer (ohne Admin), Deutsch, `.pdf`-Verknüpfung (Standard wählt man unter Windows selbst: „Öffnen mit → Immer“), `dragDropEnabled:false` damit HTML-Drag&Drop geht. Kein Code-Signing (bewusst, keine Lizenz): Windows zeigt beim ersten Start SmartScreen („Weitere Informationen → Trotzdem ausführen“).
- In der App: `window.__TAURI__` (withGlobalTauri) → `js/desktop.js` öffnet die Startdatei statt `offerRestore()`; `js/version.js` vergleicht mit `https://tablet.mps-ki.de/downloads/master-pdf/version.json` und zeigt rot „neue Version verfügbar (klicken)“ → öffnet MPSkills im Browser (opener-Plugin, nur tablet.mps-ki.de erlaubt).
- Kachel: `tools.js` `windows: '../downloads/master-pdf/'` → `fillWindowsDownloads()` in `MPSkills/app.js` zeigt „Download für Windows · V x“ neben „Öffnen“, sobald dort eine version.json liegt.
- Prüfen unter Linux: `cd desktop/master-pdf && npm install && node prepare.mjs && cd src-tauri && rustup target add x86_64-pc-windows-msvc && cargo check --release --target x86_64-pc-windows-msvc`.
