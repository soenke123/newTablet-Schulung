# CLAUDE.md — Tiny LM (MPSkills skill, Beta)

Guidance for Claude Code when working in `MPSkills/tools/TinyLM/`.

## What this is

**Tiny LM** is the eleventh MPSkills skill (migration `supabase/migrations/0210_tinylm.sql`, `beta: true` in `MPSkills/tools.js`): a German-language app that teaches students how language models work, with a small, fully transparent toy language model (no ML libraries — everything hand-rolled in vanilla JS). Students pick which texts "feed the AI" (Textwelten) and then watch, in three phases, how text is produced. It started as the stand-alone project "Wortwelten" (wortwelten-v2) and was moved here.

- **Integration**: like NeuroLab — `tool.js` mounts `index.html` in an `<iframe>` (`tl-host`/`tl-frame`, height fitted to the window), `settingsFields: []`, `update()` does nothing. Nothing is shared between devices: own texts, guide progress, open cards and the last phase live in the device's `localStorage` (`wortwelten-v2-eigene-texte`, `wortwelten-v3-text-bearbeitet`, `tinylm-leitfaden`, `tinylm-panel-offen`, `tinylm-phase`, `tinylm-textwelt-reiter`, `tinylm-p3-kontext`). The icon is `tinylm` in `MPSkills/lib/icons.js`.
- **Beta scope (decided by Sönke, 14.10.2026)**: ONE view for everybody — no teacher/student split yet (that comes once the single view is right) and no interactive preview tile (no `preview/tinylm.js`).
- **Theme**: `app.js` copies `data-theme` from the surrounding MPSkills page (same origin) and follows it live; standalone it uses `prefers-color-scheme`.
- **Fonts**: local only (`../../../fonts/outfit-inter-jetbrainsmono-985fda.css`, same set as MPSkills). Never add Google Fonts or a CDN (Datenschutz, see root CLAUDE.md).

Vanilla HTML/CSS/JS, no build step, no modules — plain `<script>` tags in dependency order (see `index.html`; bump the `?v=` stamps there and in `tool.js` when shipping). Opens directly via `file://` or any static server.

## Running / verifying

No build/test tooling; drive it in a browser (Playwright with the preinstalled Chromium works well). Check at least:
- The **Leitfaden** can be completed end to end (6 + 5 + 4 tasks; each ticks itself when actually done, strictly in order within a phase), "Zeig mir wo" opens the right card and pulses the right control, the "Aha" flashes, the tabs show `x/y` / ✓.
- Phase 1: writing, n-slider 1–6 and Zufall slider **while** writing (sliders must survive — see live-refresh rule), source colors.
- Phase 2: a matching question, an unknown one (Eiffelturm), "Dieselbe Frage nochmal", the Wortkarte (collapsed by default) and tapping a word.
- Phase 3: train, **stop again**, loss line falls, predict before/after, Netz-Bild + tap a neuron; switch phases and come back — the trained net must still be there; change texts → "Netz neu bauen" banner.
- Every ? button opens a small card (popover on wide screens, bottom sheet ≤ 560 px) and closes on outside tap/Esc/×.
- No horizontal scroll at 390 / 820 / 1024 / 1366 px, dark mode, `prefers-reduced-motion`.

## UI principles (why it looks like this)

Feedback that drove the current UI: the earlier version had long explanation boxes on every card and students did not understand what to do. So:

1. **No explanation prose on cards.** Cards show only what the machine is doing right now (live strips, bars, sliders, one short line). Explanations live behind small **?** buttons (`js/help.js`): icon, title, max two short sentences and a tiny wordless picture (`vis`: tokens, bars, cycle, scale, swatch, line, abc, dots, net). All texts are in the `HELP` table — edit them there, keep them short.
2. **A visual guide (Leitfaden) to follow along** (`js/guide.js`), sticky under the top bar: numbered dots + the current task + "Zeig mir wo". Tasks tick themselves from events the phases report (`Guide.did(type, data)` — see the header comment for the event list). After a task: a short "Aha" (replaces the old "Merk dir" boxes). Optional `nudge` tells a student who skipped ahead what comes first (max once a minute). Phase complete → "Was hab ich gelernt?" (all Ahas) + "Weiter zu Phase n".
3. **Phases are mounted once and only hidden** (`app.js goPhase`). `mount(host)` returns `{ reveal(cardId), onHide(), onShow() }`; `onHide` stops running loops. (Before, every phase switch rebuilt everything — the trained net was lost and the training loop kept running invisibly.)
4. Look follows MPSkills (Outfit/Inter, cool paper, green accent, round cards, `tokens.css`).

## The three phases

The text selection (`state.js`) is shared by all three phases — "one corpus, three ways to use it".

1. **Phase 1 — `phase1.js`, "Frei schreiben"**: count-based next-word generation (n-gram lookup + sampling), context length n = 1–6, every word tinted with its source text's color (`sourceColor(si)`), seams where it jumps between texts. Cards: Kontextfenster (n slider) · Kandidaten & Zufall · Herkunft.
2. **Phase 2 — `phase2.js`, "Frage & Antwort"**: same engine, but a question first retrieves the top-3 texts (`retrieve.js`); answer words tinted `--src-a/b/c`. At a sentence start, sentences containing a question word are strongly preferred (`ngram.js pushCandidate(…, atStart)`), otherwise answers often started off-topic. Cards: Nachschlagen · Quellen · Wort für Wort · Zufall (+ "Dieselbe Frage nochmal") · wide Wortkarte.
3. **Phase 3 — `phase3.js`, "Echtes Netz"**: a real tiny neural LM (embedding → tanh hidden → softmax, Bengio-2003-style, no attention), trained live via hand-rolled backprop (`phase3-net.js`), time-sliced over `requestAnimationFrame`. The center card holds "Vorhersagen" (paper + buttons) and the training box (toggle, reset, live loss line). The shown loss is the mean of the last 25 measurements (single values jump); `lossHistory` is compressed (older values averaged pairwise) instead of cut, so the whole learning curve stays visible. Generated words use the corpus' usual capitalisation (`data.display`). **Context length** (how many words the net sees) is chosen in the center card: 3 · 4 · 5 (`P3_CTX`, stored in `tinylm-p3-kontext`); a different window is a different net, so a change calls `render()` (new data + new net). **Learning rate decays** (`lrAt` in `phase3-net.js`): 0,15 → half after 4 passes over all examples → min 0,01, shown as „Schrittgröße“ on the Training card. With the old fixed 0,08 the loss got stuck around 2,1 and then rose again; now it reaches ≈ 1 after ~30 s in Chromium (3 words) and falls lower with 4/5 words (more memorising). Measure offline with plain `new Function` over the four engine files — Node's `vm` contexts make the loops ~20× slower. Cards: Embedding · Hidden-Schicht · Ausgabe · Training (display only) · wide "Das Netz von innen" (collapsed).

   **Live-refresh rule (don't break the stop button again).** Anything updated several times per second must never rebuild controls: an element replaced between `pointerdown` and `pointerup` never gets its `click` (that is how training once could not be stopped). Phase-3 cards and Phase-1's Kontext/Kandidaten cards are `manual: true` and register updaters in `live[id]` that only refresh numbers/canvases; the training buttons live only in the center card, which is never rebuilt while training runs (`syncTrainUI()` only changes text/classes).

## The Panel (`panel.js`)

Center "machine" card (left, sticky under the header on wide screens) + a color-coded list of cards on the right (stacks below on ≤ 980 px). Each card: step badge (`hint`), title, chevron, **?** (`help` key). Cards collapse individually (state per phase in `localStorage tinylm-panel-offen`); a closed card is not rendered at all. `wide: true` puts a card full-width below; `manual: true` excludes it from `refreshAll()`.

**Color carries meaning** (`CAT` in `panel.js`, `--cat-*` in `tokens.css`): `origin` amber (Herkunft/Quellen/Embedding), `context` teal (Kontextfenster/Nachschlagen/Hidden), `candidates` coral (Kandidaten/Wort für Wort/Ausgabe), `random` violet (Zufall/Training), `meaning` blue (Wortkarte), `net` neutral (Netz-Bild). The flow band (`flow.js`, `Flow.render` + `Flow.pulse` on every new word), card stripes, ? buttons, sliders and probability bars all use the role color. `--src-a/b/c` is a second, finer layer (which of the three Phase-2 sources).

### Shared engine modules (used by 2+ phases)

- **`vocab.js`** — `tokenize()`, `STOP` list, `SUFFIXES`, `createLemmatizer()` (closure-based suffix-stripping lemmatizer, only strips an ending if the stem also occurs in the corpus), `isContentTok()`, `showWord()` (capitalized display form for word lists/chips — distinct from the flowing-text display, see `ngram.js`'s `pieces()`).
- **`ngram.js`** — the generation engine shared by Phase 1 and Phase 2: `buildSources()`, `createSession()`, `candidates()` (tries context length n → n-1 → … → 1 → sentence-start fallback, generalizing the old prototype's fixed trigram→bigram→start chain), `pickFrom()`, `commitWord()`, `step()`, and `pieces()` (flowing-text rendering using each chosen token's *original* casing, not the lowercased canonical form used for matching — this is what gets German noun capitalization right without needing the old prototype's separate uppercase-frequency tracking).
- **`cooccurrence.js`** — `buildModel()`: PPMI co-occurrence vectors + cosine similarity, used **only** by Phase 2 (retrieval and the "ähnliche Wörter" chips; the word map only borrows its lemmatizer). Also provides `themeOf()` (which Wortwelten a word comes from, for the map's theme colors), `topContexts()` and `sharedContexts()` (the "warum ähnlich?" explanation).
- **`wordmap.js`** — `WordMap.create(M, {highlight, onSelect, texts})` → `{mount, destroy, select, redraw}`: the 2D word map, ported from the old prototype's layer 4 on explicit user request ("im Prototypen gab es auch eine Wortkarte, das war cool"). **One map for all words, the filters only highlight** (rebuilt 15.10.2026 after „wirkt gefakt, alle Wörter gleich weit auseinander; ich dachte, mit den Filtern kann ich Gruppen im Cluster hervorheben“): words = 140 most frequent nouns + 70 verbs + all pair words, as written (wordkinds model with `window: WIN` = 4, i.e. neighbour right before/after + content words in the same sentence), then **compressed to `DIMS` = 20 directions and centred** (`denseSim`: top eigenvectors of the similarity matrix) — the raw sparse vectors made 93 % of all pairs ≈ 0 % similar, so any layout became an even carpet. Layout = own t-SNE over each word's 18 nearest neighbours (`makeLayout`, perplexity 6, **step size 1** — with 5 groups shot off along the axes as a cross); measured: of each word's 3 most similar words, 87 % land among its 10 nearest on the map. Grey lines = each word's `KNN` = 3 most similar. Filter chips Alle Wörter · Nomen · Verben · spielt → spielte · Lehrer → Lehrerin and the clickable Textwelten in the legend dim everything else (no relayout); pair filters draw one arrow per pair and offer „⇉ Pfeile nebeneinander“, which glides the pair words into a fixed view computed honestly from the map's own 20-D vectors (`pairProj`: PCA of the pair words, then only rotated so the mean arrow points right — nothing forced; the old `WordKinds.projection` put the mean pair direction on x and made arrows parallel by construction). Measured: arrows vs. mean direction cos ≈ 0,91 (Lehrer → Lehrerin) in that view, but only ≈ 0,09 on the t-SNE map — t-SNE keeps neighbourhoods, not directions (feedback 15.10.2026 „von Arzt zu Ärztin ist nicht gleich zu Lehrer → Lehrerin“); the ? text says so. A small pair-only model still drives Wort-Rechnen on the detail card. Phase-2 question words (lemmas) are mapped to map words via `M.lemma` (`resolve`). Model + layout are computed **lazily on first mount** and the layout is animated over `requestAnimationFrame` (the card ships collapsed); `prefers-reduced-motion` runs it to completion in one go. Used only by Phase 2.
- **`wordkinds.js`** — `WordKinds.analyze(texts)` / `model(A, rows, {window})` / `predict(M, pairs, w)`: the second word model behind the Wortkarte filters. Words exactly as written (no lemmatizer, so „spielte“ stays), features = the word directly before/after (incl. der/die/er/heute/gestern — that is where gender and tense show), plus with `window` > 0 the content words in the same sentence up to that distance (topic). Verbs are recognised by position (after er/sie/heute…, after „der Hund“, after a name at sentence start), tense by time words in the sentence + pairs; which two words form a pair comes from small rules/lists (-in, umlaut + -in, STRONG verb table, „-t → -te“) — that part is given, only the positions are learned. `predict` uses the mean direction of the OTHER pairs (leave-one-out). Measured on the default corpus (pair-only model, window 4): Lehrer→Lehrerin 20/26 hits, spielt→spielte 15/44.
- **`netview.js`** — `NetView.create({getNet, getData, getForward, getProbs, getCtxIds, wordLabel})` → `{mount, update, destroy}`: the live, honest picture of the Phase-3 net on a canvas — `C·d` input dots, `H` hidden dots, the `SHOW` = 8 most probable output neurons plus a dashed "+ N weitere" marker, and **real edges**: every line is an actual `net.W1`/`net.W2` weight (warm `--src-a` = positive, cool `--src-b` = negative, opacity/width by magnitude, bucketed into 8 canvas paths so ~2 300 lines stay cheap). A neuron's fill is its current value, clicking one opens its real numbers (value, bias, strongest in/outgoing weights, and for hidden neurons which words it pushes up or down), and a chip row filters to the strongest 10 %/30 %/all edges. Below the canvas a `.net-facts` block answers "how many neurons/weights is this?" in German-formatted numbers. `update()` only redraws — it never rebuilds controls (see the live-refresh rule above). Used only by Phase 3.
- **`retrieve.js`** — `questionLemmas()`, `retrieve()`: question → known/unknown/similar lemmas → IDF-weighted document scoring with a similarity fallback (`SIM_MIN = 0.3`).
- **`heat.js`** — `Heat.render(container, candidates, opts)`: the one shared probability-display component for all three phases (count-based candidates in 1/2, softmax output in 3), so the same visual language reinforces "it's always a probability, just computed differently." `opts.accent` tints the bar gradient to the calling card's category color (see the Panel UI section above). See the file header for the candidate shape contract.
- **`state.js`** — `State`: tiny pub/sub + the corpus-selection store (`selectedIds`, debounced `scheduleRebuild()`). Phase 1/2 rebuild immediately on `corpus-changed`; the Textwelten drawer (`app.js renderDrawer`) has one tab per world (checkbox = whole world on/off, x/y selected) and shows all texts of the open tab expanded side by side — unchecked = greyed, edited = coral frame + word diff against the original (`wordDiff`, LCS) + „↺ Zurücksetzen“; Phase 3 deliberately does **not** auto-rebuild (expensive retrain) — it shows a "Netz neu bauen" banner.
- **`corpus.js`** — `THEMES`/`TEXTS` (the 61-text default corpus in six Textwelten: Sonnensystem, Haustiere, Wie lernt eine KI?, Schulalltag, Berufe, Küste und Meer — rewritten 14.10.2026; the header comment lists what is built in on purpose: bridges between worlds (Maus, Netz, „lernt aus vielen Beispielen“/„durch Belohnung“, Mond/Sterne), word pairs for vector arithmetic (Lehrer/Lehrerin … in parallel sentences, Präsens/Präteritum with heute/gestern right before the verb), the deliberately one-sided Berufe (Chefin, Ärztin, Krankenpfleger) and two `fake: true` texts (flat Earth loses against five „Die Erde ist eine Kugel“; Pluto-Mobbing wins „Pluto ist ein …“ 3:2 because the topic is rare). Check those counts with a quick script when editing texts) + own-text persistence (`localStorage`, key `wortwelten-v2-eigene-texte` — **different key** from the old prototype's, so the two don't collide if both are opened on the same machine). Built-in texts are **editable too**: `updateText()/resetText()` store an override per text id under `wortwelten-v3-text-bearbeitet` (v3 since the new corpus — overrides are keyed by index) and leave the `TEXTS` array itself untouched, so "Original wiederherstellen" always works. `allTexts()` applies the overrides and flags them with `edited: true`.

### Key conventions

- All UI strings and in-app data (titles, comments) are German, matching the target audience — keep new user-facing text in German.
- `el(tag, cls, text)` and `$(id)` (defined in `app.js`) are the DOM-builder helpers used everywhere; there's no framework/virtual DOM — render functions call `container.replaceChildren()` and rebuild.
- Each phase module is a single `Phases.register(n, { mount(host) {...} })` call containing all of that phase's closures; `mount` runs once and returns `{ reveal, onHide }`; `render()` inside it runs initially and again on reset/corpus-change.
- Colors are CSS custom properties in `tokens.css` — the MPSkills base (cool paper, green `--accent`), the `--cat-*` category colors (see above), `--src-a/b/c` (specific source A/B/C, Phase 2 only), and `--t-*` (Textwelten theme colors, also used by the word map) — with a `prefers-color-scheme: dark` block and a `data-theme` override (set from the MPSkills page), all color layers re-tuned for dark mode.
- `<script>` order in `index.html` matters (no modules): `app.js` (defines the `el()`/`$()` DOM helpers and the `Phases` registry) loads before `infobox.js`/`help.js`/`guide.js`/`panel.js`/`flow.js`/`vocab.js`/`ngram.js`/`heat.js`; `wordmap.js` needs `cooccurrence.js`, `wordkinds.js` and `infobox.js` and loads before `phase2.js`; `netview.js` needs `infobox.js` and loads after `phase3-net.js` and before `phase3.js`; the phase files load before `main.js` (the one-line bootstrap).

- Small shared builders: `Info.slider({...})` (slider with value, ends, optional ?, `data-spot`), `Info.centerHead(kicker, title, helpKey)`, `sourceChips(rows)` (phase1.js) for color legends. `data-spot="…"` marks what "Zeig mir wo" may highlight (`App.spotlight(spot, card)`, falls back to `[data-help=…]` / `[data-card=…]`).
- Globals declared with `const` (`Guide`, `Help`, `App`, …) are NOT on `window` — test with `typeof Guide !== 'undefined'`, not `window.Guide`.
