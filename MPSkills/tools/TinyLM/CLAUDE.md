# CLAUDE.md — Tiny LM (MPSkills skill, Beta)

Guidance for Claude Code when working in `MPSkills/tools/TinyLM/`.

## What this is

**Tiny LM** is the eleventh MPSkills skill (migration `supabase/migrations/0210_tinylm.sql`, `beta: true` in `MPSkills/tools.js`): a German-language app that teaches students how language models work, with a small, fully transparent toy language model (no ML libraries — everything hand-rolled in vanilla JS). Students pick which texts "feed the AI" (Textwelten) and then watch, in three phases, how text is produced. It started as the stand-alone project "Wortwelten" (wortwelten-v2) and was moved here.

- **Integration**: like Balance of Nature — `tool.js` mounts `index.html` in an `<iframe>` (`tl-host`/`tl-frame`, height fitted to the window) with `?raum=lehrer` (presenter) or `?raum=schueler`, `settingsFields: []`. The only shared thing is **which phases the class may open**: `skill_room_state.data.phases = [1, 2]` (missing = `[1]`), written with `ctx.actions.setData` (plain `skill_room_set_state`, no own tables). Messages (same origin): in `{type:'tl:cmd', phases}`, out `{type:'tl:ready'}` and `{type:'tl:phases', phases}` (teacher changed them). Everything else stays on the device: own texts, open cards, last phase in `localStorage` (`wortwelten-v2-eigene-texte`, `wortwelten-v3-text-bearbeitet`, `tinylm-reiter-offen`, `tinylm-phase`, `tinylm-textwelt-reiter`, `tinylm-p3-kontext`), seen explanation windows in `tinylm-erklaert-<lehrer|schueler|allein>` (students in `sessionStorage` — class tablets change hands). The icon is `tinylm` in `MPSkills/lib/icons.js`.
- **Teacher / class (29.10.2026, replaces the „one view for all“ beta scope)**: the teacher always sees all three phases and shares each one directly with **the share symbol next to its tab** (`.phase-share`, same icon and on/off behaviour as in Definitions Derby: filled = shared, tap again = take back; no extra menu — Sönke 29.10.2026). Students only see shared phases (unshared tabs are hidden); with none shared they get the „Gleich geht’s los“ wait card (`showWait`); if the phase they are in is taken back they jump to a shared one. Standalone (no `?raum=`) and in the Schaufenster everything is open.
- **Schaufenster** (23.10.2026): `MPSkills/preview/tinylm.js` — Kachel-Standbild (Satz mit Kontextfenster + Kandidaten-Balken, Hover: „Garten“ rückt nach) und Drehbuch durch alle drei Phasen (klickt `[data-spot=play|train|gen|reset|genreset|netreset]`, `.phase-btn[data-n=…]`, `.qform`, opens the Training Reiter via `.panel-item.closed[data-card=train] .panel-item-head`; keep those selectors stable — the teacher's share buttons sit between the tabs, so never select tabs with `:nth-child`). The preview frame gets `?demo=1`: `js/demo.js` (loaded first) swaps `localStorage` for an in-memory store, so the preview always starts fresh and never touches the device's state; explanation windows never open by themselves in the demo.
- **Theme**: `app.js` copies `data-theme` from the surrounding MPSkills page (same origin) and follows it live; standalone it uses `prefers-color-scheme`.
- **Fonts**: local only (`../../../fonts/outfit-inter-jetbrainsmono-985fda.css`, same set as MPSkills). Never add Google Fonts or a CDN (Datenschutz, see root CLAUDE.md).

Vanilla HTML/CSS/JS, no build step, no modules — plain `<script>` tags in dependency order (see `index.html`; bump the `?v=` stamps there and in `tool.js` when shipping). Opens directly via `file://` or any static server.

## Running / verifying

No build/test tooling; drive it in a browser (Playwright with the preinstalled Chromium works well). Check at least:
- In all three phases the columns start **closed** (Phase 3: Training open) and the phone looks like a plain LLM; opening a column shows its layer in the phone; each column's ? opens its explanation window (1366 and 390 px); in `?demo=1` all columns are open except Netz von innen.
- **Teilen**: `?raum=lehrer` → the share symbol next to each tab toggles and sends `tl:phases`; `?raum=schueler` → wait card until `tl:cmd`, unshared tabs hidden, taking back the current phase moves the student on.
- Phase 1: writing, n-slider 1–6 and Zufall slider **while** writing (sliders must survive — see live-refresh rule), source colors.
- Phase 2: a matching question, an unknown one (Eiffelturm → „Der Eiffelturm ist …“ + Ausgedacht-Hinweis), "Dieselbe Frage nochmal", tapping a word in the phone (all three columns follow), each column's layer in the phone, ↻ Nochmal brings back the suggestions.
- Phase 3: train (Training is open at first), close it while training (keeps running), **stop** while the columns refresh live, loss line falls, predict before/after, tap a predicted word (columns show that step), Netz-Bild + tap a neuron; switch phases and come back — the trained net must still be there; change texts → "Netz neu bauen" banner in the phone.
- Explanation windows have no horizontal scrollbar (content scrolls in `.ex-box`, the arrow sits on `.ex-pop`).
- Every ? button opens a small card (popover on wide screens, bottom sheet ≤ 560 px) and closes on outside tap/Esc/×.
- No horizontal scroll at 390 / 820 / 1024 / 1366 px, dark mode, `prefers-reduced-motion`.

## UI principles (why it looks like this)

Feedback that drove the current UI: the earlier version had long explanation boxes on every card and students did not understand what to do. So:

1. **No explanation prose on cards.** Cards show only what the machine is doing right now (live strips, bars, sliders, one short line). Explanations live behind small **?** buttons (`js/help.js`): icon, title, max two short sentences and a tiny wordless picture (`vis`: tokens, bars, cycle, scale, swatch, line, abc, dots, net). All texts are in the `HELP` table — edit them there, keep them short.
2. **Clean first, then guided — Reiter + explanation window, no tour** (since 02.11.2026 all three phases use the phone + columns view, see „The three phases“; the Panel-based first-open windows and the „Schau mal!“ pulse below are no longer used) (Sönke 01.11.2026: „erstmal sehr clean … dann ein bisschen durchgeführt werden“; the tour boxes „sind ganz cool, aber … nicht als Tour, sondern dass man immer einmal das hat … nur die Reiter da rechts und da unten“). Everything on the right (and the wide cards below) is a **Reiter** that starts collapsed as a slim term (`panel.css` `.panel-item.closed`). The first time a Reiter is opened, `js/erklaerung.js` (`Explain.firstOpen`) dims the page, frames the card in its category color and puts a window next to it: icon + title, the mini picture (`Help.vis`), 1–2 sentences „what you find here“ and a „Probier mal:“ line — all from `HELP` in `help.js` (`text`, `try`). Seen per `<phase>:<id>`. The card's ? shows the same window again (`Explain.show`). Guidance: `panelCtrl.guide([...ids])` makes the next not-yet-explained Reiter pulse with a „Schau mal!“ badge (Phase 1 after the first word, Phase 2 after the first question, Phase 3 once training started); in Phase 1 Tiny also says „Tipp rechts auf …“ after a pause. The top bar has brand + phase tabs + the „Alle Quellen“ button (opens the Textwelten drawer; no tour ?). Earlier attempts that are gone: Leitfaden (`guide.js`), flow band (`flow.js`), per-phase tour (`tour.js`).
3. **Phases are mounted once and only hidden** (`app.js goPhase`). `mount(host)` returns `{ reveal(cardId), onHide(), onShow() }`; `onHide` stops running loops. (Before, every phase switch rebuilt everything — the trained net was lost and the training loop kept running invisibly.)
4. **Own look „Token-Bausteine“** (Sönke 29.10.2026, design 9 of the sketch canvas: „soll wie ein echtes LLM wirken“, but playful, and stand apart from MPSkills): lavender ground, white cards and buttons with a solid edge below (`--edge`, `box-shadow: 0 3px 0`; pressed = sinks onto it), violet `--accent`, **Fredoka** (local `fonts/fredoka-1ad7b8.css`) for headings/tokens, Inter for text, JetBrains Mono for numbers. LLM vocabulary where it fits (Token, tiny · model line under the brand). Generated text = **token blocks** (`.srcword`/`.tok` in `base.css`: one chunky tile per word in its source color, punctuation glued to the tile before, `.win` = context window, the `.cursor` is a dashed „?“ tile). **Tiny**, the mascot (`tinySvg(mood)`/`tinyEl()` in `app.js`: round robot head, moods normal/happy/think) sits in the brand, says in Phase 1 what it is doing (`.tiny-say`, `markWindow` in `phase1.js`), answers in the Phase-2 chat and in Phase 3 says how the net is doing (`updateSay`: untrained → „Training starten“, loss while training, what it sees and expects while predicting). The center card looks the same in every phase: head · paper · Tiny · buttons. Candidates are columns (`heat.js`, height = absolute probability, max 5 columns). Category colours stay as numbered badges on the cards (no left stripe).

Layers in the phone: Embedding → `.win` on the last C tokens; Kandidaten → „?“ tile and Tiny's „ich sehe … am ehesten …“; Hidden-Schicht → a neuron strip in the phone (`.phone-neurons`). **Tapping a predicted word** deconstructs that step: `doGenStep` stores per word `ctxIds`, `logits`, `h` (what the net saw and computed then). The shown loss is the mean of the last 25 measurements (single values jump); `lossHistory` is compressed (older values averaged pairwise) instead of cut, so the whole learning curve stays visible. With the old fixed 0,08 the loss got stuck around 2,1 and then rose again; it reached ≈ 1 after ~30 s in Chromium (3 words) with 61 texts; with 85 texts (6 626 examples, 12 % of targets `<unk>` because of the 600-word cap) it is ≈ 1,7 after 30 s and falls lower with 4/5 words (more memorising). Measure offline with plain `new Function` over the four engine files — Node's `vm` contexts make the loops ~20× slower. 

   **Live-refresh rule (don't break the stop button again).** Anything updated several times per second must never rebuild controls: an element replaced between `pointerdown` and `pointerup` never gets its `click` (that is how training once could not be stopped). In Phase 3 the training tick (`liveTick`) only repaints the column bodies (nothing tappable inside — candidate rows are `div`s there), the neuron strip and the net picture; the training toggle, the Temperatur slider and the 3 · 4 · 5 picker sit in fixed `.p1-col-tools` heads, `live.train` only changes numbers and the loss line, `syncTrainUI()` only text/classes of the toggle, and the „Du zerlegst …“ banner is not touched by the tick.

## The Panel (`panel.js`)

No phase uses `Panel.mount` any more (all three use the phone view); `panel.js` still provides `CAT` (category colors for the explanation windows). Earlier: center "machine" card (left) + a color-coded list of Reiter on the right (stacks below on ≤ 980 px). Each card: step badge (`hint`, or `icon`), title, optional `meta` text, chevron, **?** (`help` key → explanation window). Cards collapse individually and **start collapsed** (`open: true` to override; state per phase in `localStorage tinylm-reiter-offen`); a closed card is not rendered at all. `guide(ids)`/`nextItem()`/`onGuide` drive the „Schau mal!“ pulse, `updateMeta()` refreshes the head texts. `wide: true` puts a card full-width below; `manual: true` excludes it from `refreshAll()`.

**One structure for all three phases** (decided by Sönke, 21.10.2026: „Begriffe und Colorgrading sprechen eine Sprache und helfen bei der Orientierung“). Every phase has the same four numbered steps in the same place (the explanation windows use the same names and numbers):

| Step | Phase 1 | Phase 2 | Phase 3 | Color (`CAT` in `panel.js`, `--cat-*` in `tokens.css`) |
|---|---|---|---|---|
| ① what the AI looks at | Kontextfenster | Frage zerlegen | Embedding | teal family: `context` / `ask` (cyan) / `embed` (petrol) |
| ② where the word comes from | Quellen | Quellen | Hidden-Schicht | amber family: `origin` / `hidden` (bronze — knowledge now lives in numbers) |
| ③ | Kandidaten | Kandidaten | Kandidaten | `candidates` coral |
| ④ | Zufall | Zufall | Zufall | `random` violet |

Same slot but a different thing → a shade of the same family; not a step at all → own color and no number: `texts` slate indigo (Textwelten Reiter), `meaning` blue (Wortkarte), `train` magenta (Training — runs beside writing, not per word; also the loss line, train dot, trained context chips), `net` neutral (Netz-Bild, whose layers use `embed`/`hidden`/`candidates`). Don't merge terms that only sound alike (old „Nachschlagen“ ≠ „Nachsehen“) and keep the help titles equal to the card titles (one exception on purpose: Zufall — card/band „Zufall“, slider label „Temperatur“, help title „Zufall (Temperatur)“, so the real term appears without breaking the structure). Card badges, explanation frames, ? buttons, sliders and probability bars all use the role color. `--src-a/b/c` is a second, finer layer (which of the three Phase-2 sources).

### Shared engine modules (used by 2+ phases)

- **`vocab.js`** — `tokenize()`, `STOP` list, `SUFFIXES`, `createLemmatizer()` (closure-based suffix-stripping lemmatizer, only strips an ending if the stem also occurs in the corpus), `isContentTok()`, `showWord()` (capitalized display form for word lists/chips — distinct from the flowing-text display, see `ngram.js`'s `pieces()`).
- **`ngram.js`** — the generation engine shared by Phase 1 and Phase 2: `buildSources()`, `createSession()`, `candidates()` (tries context length n → n-1 → … → 1 → sentence-start fallback, generalizing the old prototype's fixed trigram→bigram→start chain), `pickFrom()`, `commitWord()`, `step()`, and `pieces()` (flowing-text rendering using each chosen token's *original* casing, not the lowercased canonical form used for matching — this is what gets German noun capitalization right without needing the old prototype's separate uppercase-frequency tracking).
- **`cooccurrence.js`** — `buildModel()`: PPMI co-occurrence vectors + cosine similarity, used **only** by Phase 2 (retrieval and the "ähnliche Wörter" chips; the word map only borrows its lemmatizer). Also provides `themeOf()` (which Wortwelten a word comes from, for the map's theme colors), `topContexts()` and `sharedContexts()` (the "warum ähnlich?" explanation).
- **`wordmap.js`** — `WordMap.create(M, {highlight, onSelect, texts})` → `{mount, destroy, select, redraw}`: the 2D word map, ported from the old prototype's layer 4 on explicit user request ("im Prototypen gab es auch eine Wortkarte, das war cool"). **One map for all words, the filters only highlight** (rebuilt 15.10.2026 after „wirkt gefakt, alle Wörter gleich weit auseinander; ich dachte, mit den Filtern kann ich Gruppen im Cluster hervorheben“): words = 140 most frequent nouns + 70 verbs + all pair words, as written (wordkinds model with `window: WIN` = 4, i.e. neighbour right before/after + content words in the same sentence), then **compressed to `DIMS` = 20 directions and centred** (`denseSim`: top eigenvectors of the similarity matrix) — the raw sparse vectors made 93 % of all pairs ≈ 0 % similar, so any layout became an even carpet. Layout = own t-SNE over each word's 18 nearest neighbours (`makeLayout`, perplexity 6, **step size 1** — with 5 groups shot off along the axes as a cross); measured: of each word's 3 most similar words, 87 % land among its 10 nearest on the map. Grey lines = each word's `KNN` = 3 most similar. Filter chips Alle Wörter · Nomen · Verben (the pair chips spielt → spielte · Lehrer → Lehrerin and „Pfeile nebeneinander“ are switched off since 11.11.2026 — Sönke: the multi-dimensionality does not come across, „es wirkt, als wenn das Programm sie absichtlich nebeneinander packt“; the code below stays, re-enable by putting the two entries back into `FILTERS`) and the clickable Textwelten in the legend dim everything else (no relayout); pair filters draw one arrow per pair and offer „⇉ Pfeile nebeneinander“, which glides the pair words into a fixed view computed honestly from the map's own 20-D vectors (`pairProj`: PCA of the pair words, then only rotated so the mean arrow points right — nothing forced; the old `WordKinds.projection` put the mean pair direction on x and made arrows parallel by construction). Measured: arrows vs. mean direction cos ≈ 0,91 (Lehrer → Lehrerin) in that view, but only ≈ 0,09 on the t-SNE map — t-SNE keeps neighbourhoods, not directions (feedback 15.10.2026 „von Arzt zu Ärztin ist nicht gleich zu Lehrer → Lehrerin“); the ? text says so. A small pair-only model still drives Wort-Rechnen on the detail card. Phase-2 question words (lemmas) are mapped to map words via `M.lemma` (`resolve`). Model + layout are computed **lazily on first mount** and the layout is animated over `requestAnimationFrame` (the card ships collapsed); `prefers-reduced-motion` runs it to completion in one go. Currently used by no phase (since 11.11.2026; still loaded in `index.html` for the planned Wortwolken phase).
- **`wordkinds.js`** — `WordKinds.analyze(texts)` / `model(A, rows, {window})` / `predict(M, pairs, w)`: the second word model behind the Wortkarte filters. Words exactly as written (no lemmatizer, so „spielte“ stays), features = the word directly before/after (incl. der/die/er/heute/gestern — that is where gender and tense show), plus with `window` > 0 the content words in the same sentence up to that distance (topic). Verbs are recognised by position (after er/sie/heute…, after „der Hund“, after a name at sentence start), tense by time words in the sentence + pairs; which two words form a pair comes from small rules/lists (-in, umlaut + -in, STRONG verb table, „-t → -te“) — that part is given, only the positions are learned. `predict` uses the mean direction of the OTHER pairs (leave-one-out). Measured on the default corpus (pair-only model, window 4): Lehrer→Lehrerin 20/26 hits, spielt→spielte 15/44.
- **`netview.js`** — `NetView.create({getNet, getData, getForward, getProbs, getCtxIds, wordLabel})` → `{mount, update, destroy}`: the live, honest picture of the Phase-3 net on a canvas — `C·d` input dots, `H` hidden dots, the `SHOW` = 8 most probable output neurons plus a dashed "+ N weitere" marker, and **real edges**: every line is an actual `net.W1`/`net.W2` weight (warm `--src-a` = positive, cool `--src-b` = negative, opacity/width by magnitude, bucketed into 8 canvas paths so ~2 300 lines stay cheap). A neuron's fill is its current value, clicking one opens its real numbers (value, bias, strongest in/outgoing weights, and for hidden neurons which words it pushes up or down), and a chip row filters to the strongest 10 %/30 %/all edges. Below the canvas a `.net-facts` block answers "how many neurons/weights is this?" in German-formatted numbers. `update()` only redraws — it never rebuilds controls (see the live-refresh rule above). Used only by Phase 3.
- **`retrieve.js`** — `questionLemmas()`, `retrieve()`: question → known/unknown/similar lemmas → IDF-weighted document scoring with a similarity fallback (`SIM_MIN = 0.3`).
- **`heat.js`** — `Heat.render(container, candidates, opts)`: the one shared probability-display component for all three phases (count-based candidates in 1/2, softmax output in 3), so the same visual language reinforces "it's always a probability, just computed differently." `opts.accent` tints the bar gradient to the calling card's category color (see the Panel UI section above). See the file header for the candidate shape contract.
- **`state.js`** — `State`: tiny pub/sub + the corpus-selection store (`selectedIds`, debounced `scheduleRebuild()`). Phase 1/2 rebuild immediately on `corpus-changed`; the Textwelten drawer (`app.js renderDrawer`) has one tab per world (checkbox = whole world on/off, x/y selected) and shows all texts of the open tab expanded side by side — unchecked = greyed, edited = coral frame + word diff against the original (`wordDiff`, LCS) + „↺ Zurücksetzen“; Phase 3 deliberately does **not** auto-rebuild (expensive retrain) — it shows a "Netz neu bauen" banner.
- **`corpus.js`** — `THEMES`/`TEXTS` (the 85-text default corpus in six Textwelten (61 until 12.11.2026, then four more per world appended at the END of `TEXTS` — Ratgeber/Tagesablauf/Interview/Steckbrief style, a bit harder, so nouns recur in similar sentences; new texts must always be appended, never inserted, because edit overrides are keyed by position; retrieval only searches the body, so a text's key word must also stand in the body): Sonnensystem, Haustiere, Wie lernt eine KI?, Schulalltag, Berufe, Küste und Meer — rewritten 14.10.2026; the header comment lists what is built in on purpose: bridges between worlds (Maus, Netz, „lernt aus vielen Beispielen“/„durch Belohnung“, Mond/Sterne), word pairs for vector arithmetic (Lehrer/Lehrerin … in parallel sentences, Präsens/Präteritum with heute/gestern right before the verb), the deliberately one-sided Berufe (Chefin, Ärztin, Krankenpfleger) and two `fake: true` texts (flat Earth loses against five „Die Erde ist eine Kugel“; Pluto-Mobbing wins „Pluto ist ein …“ 3:2 because the topic is rare). Check those counts with a quick script when editing texts) + own-text persistence (`localStorage`, key `wortwelten-v2-eigene-texte` — **different key** from the old prototype's, so the two don't collide if both are opened on the same machine). Built-in texts are **editable too**: `updateText()/resetText()` store an override per text id under `wortwelten-v3-text-bearbeitet` (v3 since the new corpus — overrides are keyed by index) and leave the `TEXTS` array itself untouched, so "Original wiederherstellen" always works. `allTexts()` applies the overrides and flags them with `edited: true`.

### Key conventions

- All UI strings and in-app data (titles, comments) are German, matching the target audience — keep new user-facing text in German.
- `el(tag, cls, text)` and `$(id)` (defined in `app.js`) are the DOM-builder helpers used everywhere; there's no framework/virtual DOM — render functions call `container.replaceChildren()` and rebuild.
- Each phase module is a single `Phases.register(n, { mount(host) {...} })` call containing all of that phase's closures; `mount` runs once and returns `{ reveal, onHide }`; `render()` inside it runs initially and again on reset/corpus-change.
- Colors are CSS custom properties in `tokens.css` — the MPSkills base (cool paper, green `--accent`), the `--cat-*` category colors (see above), `--src-a/b/c` (specific source A/B/C, Phase 2 only), and `--t-*` (Textwelten theme colors, also used by the word map) — with a `prefers-color-scheme: dark` block and a `data-theme` override (set from the MPSkills page), all color layers re-tuned for dark mode.
- `<script>` order in `index.html` matters (no modules): `app.js` (defines the `el()`/`$()` DOM helpers and the `Phases` registry) loads before `infobox.js`/`help.js`/`erklaerung.js`/`panel.js`/`vocab.js`/`ngram.js`/`heat.js`; `wordmap.js` needs `cooccurrence.js`, `wordkinds.js` and `infobox.js` and loads before `phase2.js`; `netview.js` needs `infobox.js` and loads after `phase3-net.js` and before `phase3.js`; the phase files load before `main.js` (the one-line bootstrap).

- Small shared builders: `Info.slider({...})` (slider with value, ends, optional ?, `data-spot`), `Info.centerHead(kicker, title, helpKey)`, `sourceChips(rows)` (phase1.js) for color legends. `data-spot="…"` marks fixed controls the Schaufenster script clicks (`[data-card=…]` for whole cards; `App.revealCard(id)` opens a card of the active phase).
- Globals declared with `const` (`Explain`, `Help`, `App`, …) are NOT on `window` — test with `typeof Explain !== 'undefined'`, not `window.Explain`.
