# CLAUDE.md — Tiny LM (MPSkills skill, Beta)

Guidance for Claude Code when working in `MPSkills/tools/TinyLM/`.

## What this is

**Tiny LM** is the eleventh MPSkills skill (migration `supabase/migrations/0210_tinylm.sql`, `beta: true` in `MPSkills/tools.js`): a German-language app that teaches students how language models work, with a small, fully transparent toy language model (no ML libraries — everything hand-rolled in vanilla JS). Students pick which texts "feed the AI" (Textwelten) and then watch, in three phases, how text is produced. It started as the stand-alone project "Wortwelten" (wortwelten-v2) and was moved here.

- **Integration**: like Balance of Nature — `tool.js` mounts `index.html` in an `<iframe>` (`tl-host`/`tl-frame`, height fitted to the window) with `?raum=lehrer` (presenter) or `?raum=schueler`, `settingsFields: []`. The only shared thing is **which phases the class may open**: `skill_room_state.data.phases = [1, 2]` (missing = `[1]`), written with `ctx.actions.setData` (plain `skill_room_set_state`, no own tables). Messages (same origin): in `{type:'tl:cmd', phases}`, out `{type:'tl:ready'}` and `{type:'tl:phases', phases}` (teacher changed them). Everything else stays on the device: own texts, open cards, last phase in `localStorage` (`wortwelten-v2-eigene-texte`, `wortwelten-v3-text-bearbeitet`, `tinylm-reiter-offen`, `tinylm-phase`, `tinylm-textwelt-reiter`, `tinylm-p4-kontext`), seen explanation windows in `tinylm-erklaert-<lehrer|schueler|allein>` (students in `sessionStorage` — class tablets change hands). The icon is `tinylm` in `MPSkills/lib/icons.js`.
- **Teacher / class (29.10.2026, replaces the „one view for all“ beta scope)**: the teacher always sees all three phases and shares each one directly with **the share symbol next to its tab** (`.phase-share`, same icon and on/off behaviour as in Definitions Derby: filled = shared, tap again = take back; no extra menu — Sönke 29.10.2026). Students only see shared phases (unshared tabs are hidden); with none shared they get the „Gleich geht’s los“ wait card (`showWait`); if the phase they are in is taken back they jump to a shared one. Standalone (no `?raum=`) and in the Schaufenster everything is open.
- **Schaufenster** (23.10.2026): `MPSkills/preview/tinylm.js` — Kachel-Standbild (Satz mit Kontextfenster + Kandidaten-Balken, Hover: „Garten“ rückt nach) und Drehbuch durch alle drei Phasen (klickt `[data-spot=play|train|gen|reset|genreset|netreset]`, `.phase-btn[data-n=…]`, `.qform`, opens the Training Reiter via `.panel-item.closed[data-card=train] .panel-item-head`; keep those selectors stable — the teacher's share buttons sit between the tabs, so never select tabs with `:nth-child`). The preview frame gets `?demo=1`: `js/demo.js` (loaded first) swaps `localStorage` for an in-memory store, so the preview always starts fresh and never touches the device's state; explanation windows never open by themselves in the demo.
- **Theme**: `app.js` copies `data-theme` from the surrounding MPSkills page (same origin) and follows it live; standalone it uses `prefers-color-scheme`.
- **Fonts**: local only (`../../../fonts/outfit-inter-jetbrainsmono-985fda.css`, same set as MPSkills). Never add Google Fonts or a CDN (Datenschutz, see root CLAUDE.md).

Vanilla HTML/CSS/JS, no build step, no modules — plain `<script>` tags in dependency order (see `index.html`; bump the `?v=` stamps there and in `tool.js` when shipping). Opens directly via `file://` or any static server.

## Running / verifying

No build/test tooling; drive it in a browser (Playwright with the preinstalled Chromium works well). Check at least:
- In all three phases the columns start **closed** (Phase 3: Training open) and the phone looks like a plain LLM; opening a column shows its layer in the phone; each column's ? opens its explanation window (1366 and 390 px); in `?demo=1` all columns are open except Netz von innen.
- **Teilen**: `?raum=lehrer` → the share symbol next to each tab toggles and sends `tl:phases`; `?raum=schueler` → wait card until `tl:cmd`, unshared tabs hidden, taking back the current phase moves the student on.
- Phase 1: writing, n-slider 1–6 and Zufall slider **while** writing (sliders must survive — see live-refresh rule), source colors.
- Phase 2: a matching question, an unknown one (Eiffelturm → „Der Eiffelturm ist …“ + Ausgedacht-Hinweis), tapping a word in the phone (all three columns follow), each column's layer in the phone, ↻ Nochmal brings back the suggestions.
- Phase 3: train (Training is open at first), close it while training (keeps running), **stop** while the columns refresh live, loss line falls, predict before/after, tap a predicted word (columns show that step), Netz-Bild + tap a neuron; switch phases and come back — the trained net must still be there; change texts → "Netz neu bauen" banner in the phone.
- Explanation windows have no horizontal scrollbar (content scrolls in `.ex-box`, the arrow sits on `.ex-pop`).
- Every ? button opens a small card (popover on wide screens, bottom sheet ≤ 560 px) and closes on outside tap/Esc/×.
- No horizontal scroll at 390 / 820 / 1024 / 1366 px, dark mode, `prefers-reduced-motion`.

## UI principles (why it looks like this)

Feedback that drove the current UI: the earlier version had long explanation boxes on every card and students did not understand what to do. So:

1. **No explanation prose on cards.** Cards show only what the machine is doing right now (live strips, bars, sliders, one short line). Explanations live behind small **?** buttons (`js/help.js`): icon, title, max two short sentences and a tiny wordless picture (`vis`: tokens, bars, cycle, scale, swatch, line, abc, dots, net). All texts are in the `HELP` table — edit them there, keep them short.
2. **Clean first, then guided — Reiter + explanation window, no tour** (since 02.11.2026 all three phases use the phone + columns view, see „The three phases“; the Panel-based first-open windows and the „Schau mal!“ pulse below are no longer used) (Sönke 01.11.2026: „erstmal sehr clean … dann ein bisschen durchgeführt werden“; the tour boxes „sind ganz cool, aber … nicht als Tour, sondern dass man immer einmal das hat … nur die Reiter da rechts und da unten“). Everything on the right (and the wide cards below) is a **Reiter** that starts collapsed as a slim term (`panel.css` `.panel-item.closed`). The first time a Reiter is opened, `js/erklaerung.js` (`Explain.firstOpen`) dims the page, frames the card in its category color and puts a window next to it: icon + title, the mini picture (`Help.vis`), 1–2 sentences „what you find here“ and a „Probier mal:“ line — all from `HELP` in `help.js` (`text`, `try`). Seen per `<phase>:<id>`. The card's ? shows the same window again (`Explain.show`). Guidance: `panelCtrl.guide([...ids])` makes the next not-yet-explained Reiter pulse with a „Schau mal!“ badge (Phase 1 after the first word, Phase 2 after the first question, Phase 3 once training started); in Phase 1 Tiny also says „Tipp rechts auf …“ after a pause. The top bar has brand + phase tabs + the „Alle Quellen“ button (opens the Textwelten drawer; no tour ?). Earlier attempts that are gone: Leitfaden (`guide.js`), flow band (`flow.js`), per-phase tour (`tour.js`).
3. **Phases are mounted once and only hidden** (`app.js goPhase`). `mount(host)` returns `{ reveal(cardId), onHide(), onShow() }`; `onHide` stops running loops. (Before, every phase switch rebuilt everything — the trained net was lost and the training loop kept running invisibly.)
4. **Own look „Token-Bausteine“** (Sönke 29.10.2026, design 9 of the sketch canvas: „soll wie ein echtes LLM wirken“, but playful, and stand apart from MPSkills): lavender ground, white cards and buttons with a solid edge below (`--edge`, `box-shadow: 0 3px 0`; pressed = sinks onto it), violet `--accent`, **Fredoka** (local `fonts/fredoka-1ad7b8.css`) for headings/tokens, Inter for text, JetBrains Mono for numbers. LLM vocabulary where it fits (Token, tiny · model line under the brand). Generated text = **token blocks** (`.srcword`/`.tok` in `base.css`: one chunky tile per word in its source color, punctuation glued to the tile before, `.win` = context window, the `.cursor` is a dashed „?“ tile). **Tiny**, the mascot (`tinySvg(mood)`/`tinyEl()` in `app.js`: round robot head, moods normal/happy/think) sits in the brand, says in Phase 1 what it is doing (`.tiny-say`, `markWindow` in `phase1.js`), answers in the Phase-2 chat and in Phase 3 says how the net is doing (`updateSay`: untrained → „Training starten“, loss while training, what it sees and expects while predicting). The center card looks the same in every phase: head · paper · Tiny · buttons. Candidates are columns (`heat.js`, height = absolute probability, max 5 columns). Category colours stay as numbered badges on the cards (no left stripe).

The shown loss is the mean of the last 25 measurements (single values jump); `lossHistory` is compressed (older values averaged pairwise) instead of cut, so the whole learning curve stays visible. Generated words use the corpus' usual capitalisation (`data.display`). **Context length** (how many words the net sees) is chosen in the center card under the text: 3 · 4 · 5 (`P4_CTX`, stored in `tinylm-p4-kontext`); a different window is a different net, and **the three nets stay side by side** (`slots` in `phase4.js`, keyed by window, valid for one `State.corpusVersion`): train all three and switch back and forth (chips show ✓ when trained); only "Netz neu bauen" (`render(true)`) or a changed text selection discards them. **Learning rate decays** (`lrAt` in `phase4-net.js`): 0,15 → half after 4 passes over all examples → min 0,01, shown as „Schrittgröße“ on the Training card. With the old fixed 0,08 the loss got stuck around 2,1 and then rose again; it reached ≈ 1 after ~30 s in Chromium (3 words) with 61 texts; with 90 texts (7 003 examples, 10 % of targets `<unk>` because of the 600-word cap) it is ≈ 1,8 after 30 s and falls lower with 4/5 words (more memorising). Measure offline with plain `new Function` over the four engine files — Node's `vm` contexts make the loops ~20× slower. 

   **Frage als eigener Eingang (Sönke 13.11.2026: „Phase 4 fühlt sich wie ein Rückschritt an“ — Phase 2/3 antworten auf eine Frage, das Netz schrieb nur drauflos).** The phone is a chat like Phase 2/3 (`.phone-chat`: suggestions `P4_SUGGEST` + `.qform` until asked, then the question bubble with `.qw` off/known/unknown — coloured with Embedding open via `.show-ask` —, meta „⭐ Frage: frisst · Hund“ (+ „zu selten: …“ for words outside the vocab — with the 1300 cap only words of texts switched off), the answer tiles, ▶ Weiter (`gen`) · +1 Wort (`genstep`) · ↻ Nochmal (`genreset` = `resetGen`, back to suggestions); Tiny's status line stays visible all the time (training state). The net (`createNet(…, {topic: true})`) gets a **(C+1)-th input block = mean of the embeddings of the question's content words** (same table as the context words — „der Mittelpunkt der Wortwolke“, Sönke), and that block goes into the hidden layer (W1) **and directly to the output words** (`net.WQ`, d × V). Training: every pair carries `topic` = content-word ids of its text (`data.contentIds`), `drawTopic` picks 1–3 of them per step, 1 in 5 steps none (zeros) — so the net learns to stay on the text's topic. Measured offline (8 questions, 30 answers each, share of content words from the right Textwelt, 3 words window): without the input 19–21 %; input only via the hidden layer 20 % (the net learned to ignore it); with the direct path 46–52 %, already after 8 passes (51 % vs 19 %), loss per pass unchanged, ~15 % more time per step. Also tried and dropped: feeding the question words + „.“ as invisible context (lottery, 6–71 % for the same question between runs; unnatural contexts like „frisst welpe .“ never occur in training) and training that format explicitly (3× the pairs, worse after the same time). ### Shared engine modules (used by 2+ phases)

- **`vocab.js`** — `tokenize()`, `STOP` list, `SUFFIXES`, `createLemmatizer()` (closure-based suffix-stripping lemmatizer, only strips an ending if the stem also occurs in the corpus), `isContentTok()`, `showWord()` (capitalized display form for word lists/chips — distinct from the flowing-text display, see `ngram.js`'s `pieces()`).

Agreed idea: the question becomes a point in the cloud → nearest texts (search by meaning vs. keyword search in Phase 2); while writing, a word in the context may be swapped for a near word in the cloud and its continuation borrowed („Der Welpe frisst [Fleisch ≈ von Hund]“). Explicitly NOT: picking the next word as nearest neighbour (cloud nearness = can stand in the same place, not = comes next). Offline measurement on the default corpus (scratch scripts, `new Function` over vocab/corpus/cooccurrence/ngram/wordkinds):
- `cooccurrence.js` (window 4) gives topical neighbours (Hund → Tierärztin, Leckerli, Katze; Hamster → Häuschen, Papprolle); `WordKinds.model` with window 0/1 gives grammatical ones (Fisch → Heu, Fleisch, Körner; Möwe → Pilotin, Astronautin) but is noisy — the corpus has too few repeated sentence frames.
- Borrowing rarely triggers (most short contexts exist) and plain back-off already makes „new“ sentences; the honest contrast to show is back-off („vergiss Welpe“ → „frisst Körner“) vs. borrowing („Welpe ≈ Hund“ → „frisst Fleisch und Trockenfutter“).
- Projection of the noun cloud: of each word's 3 most similar words, 44 % land among its 10 nearest in 2D (PCA), 55 % in 3D, 94 % in 20D — numbers for the „eigentlich 20 Dimensionen“ hint of a rotatable 3D cloud.

### Key conventions

- All UI strings and in-app data (titles, comments) are German, matching the target audience — keep new user-facing text in German.
- `el(tag, cls, text)` and `$(id)` (defined in `app.js`) are the DOM-builder helpers used everywhere; there's no framework/virtual DOM — render functions call `container.replaceChildren()` and rebuild.
- Each phase module is a single `Phases.register(n, { mount(host) {...} })` call containing all of that phase's closures; `mount` runs once and returns `{ reveal, onHide }`; `render()` inside it runs initially and again on reset/corpus-change.
- Colors are CSS custom properties in `tokens.css` — the MPSkills base (cool paper, green `--accent`), the `--cat-*` category colors (see above), `--src-a/b/c` (specific source A/B/C, Phase 2 only), and `--t-*` (Textwelten theme colors, also used by the word map) — with a `prefers-color-scheme: dark` block and a `data-theme` override (set from the MPSkills page), all color layers re-tuned for dark mode.
- `<script>` order in `index.html` matters (no modules): `wolke.js` needs `wordkinds.js`/`ngram.js` and loads before `phase3.js` (after `phase2.js`); `app.js` (defines the `el()`/`$()` DOM helpers and the `Phases` registry) loads before `infobox.js`/`help.js`/`erklaerung.js`/`panel.js`/`vocab.js`/`ngram.js`/`heat.js`; `wordmap.js` needs `cooccurrence.js`, `wordkinds.js` and `infobox.js` and loads before `phase2.js`; `netview.js` needs `infobox.js` and loads after `phase4-net.js` and before `phase4.js`; the phase files load before `main.js` (the one-line bootstrap).

- Small shared builders: `Info.slider({...})` (slider with value, ends, optional ?, `data-spot`), `Info.centerHead(kicker, title, helpKey)`, `sourceChips(rows)` (phase1.js) for color legends. `data-spot="…"` marks fixed controls the Schaufenster script clicks (`[data-card=…]` for whole cards; `App.revealCard(id)` opens a card of the active phase).
- Globals declared with `const` (`Explain`, `Help`, `App`, …) are NOT on `window` — test with `typeof Explain !== 'undefined'`, not `window.Explain`.
